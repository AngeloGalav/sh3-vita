# J3 whole-data check (2026-11-13)

Tool: `tools/j3_check_all.py`. It imports the existing `j3_*.py` tools (none were
modified) and runs them over the whole GOG data set, comparing each count with
`docs/DATA-FORMATS-SH3.md`. Archive payloads are parsed in memory; the only files
written are a JSON report and temporary `.mdl` copies (deleted right after use),
all under `sh3-vita/build/check-scratch/`.

## Run

```
python3 tools/j3_check_all.py "<...>/Silent Hill 3/data"            # full
python3 tools/j3_check_all.py "<...>/Silent Hill 3/data" --quick    # sample, ~3 s
```

Options: `--jobs N` (processes for ADX/movies, default 3), `--scratch DIR`.
Full run on 2026-11-13: 302.0 s in the script (5:02 wall clock), peak RSS about
1.9 GB, exit code 0. Evidence (not versioned): `sh3-vita/build/check-scratch/`
(`report-full.json`, `full-run.txt`, `full-time.txt`).

## What "OK" means per format

- **arc validate**: `j3_arc.cmd_validate` output parsed; every archive line must be OK and the summary must say ALL OK.
- **`.map`**: `map_sections` yields top-level sections, the inner `ffffffff` container walks, its last sub ends exactly at EOF, and `decode_container` succeeds.
- **`.cld`**: `j3_cld.parse` completes (its asserts hold).
- **`.cam`**: size is a multiple of 0x80 and `j3_cam.records` runs; records are summed across files.
- **`.kg2` / `.lv`**: `j3_kg2.parse` consumes the file exactly to EOF. 48 `.kg2` files are zero bytes and are skipped, as in the docs; `.lv` has none.
- **`.mdl`**: the tool's own `j3_mdl.survey()` on a temporary copy (outer header, model directory, every byte assigned to a region, model block ends at the texture container or EOF).
- **`.mes`** (not in the requested list): offset table is sane and `decode_text` runs. A weak check; the format is only partly decoded.
- **ADX**: `adx_decode` succeeds and the decoded sample count equals the header total. Covers 38 AFS files (37 in `sound/demo_afs/` plus `sound/sd.afs`; the 372 includes the 4 raw ADX of `sd.afs`).
- **Movies**: `j3_movie.check` on all 7 files, 235,980 sectors, 0 bad.

## Caveats

- **`.anm` has no parser** in `tools/`; the row is a file count only (OK shown as n/a). The MATCH means the count is 92, not that any file was decoded here.
- `DATA-FORMATS-SH3.md` is inconsistent in two places: 933 vs 934 plausible `.cam` records (measured 934), and "39 AFS" vs 38 found.
- `--quick` samples 8 entries per format, the 6 smallest ADX and the smallest movie; its verdicts read SAMPLE and prove nothing about the full counts.
- Checked on PC only. Nothing here is a console or Vita validation.
